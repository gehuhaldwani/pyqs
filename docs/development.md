# Development

## Setup

Follow the [quick start](../README.md#quick-start) to clone both branches and start the dev server. The site expects the papers in `pyqs/` at the project root.

To test the site on a phone on the same network, run `bun run dev:public` and open the address it prints.

## Project layout

```text
src/
  content.config.ts   the fs collection and its loader rules
  pages/              [...slug].astro for folders and files, plus about, contribute, 404
  layouts/            page frames for folders, docs, PDFs and markdown pages
  components/
    partials/         head tags, fonts, prose wrapper
    ui/               header, footer, NavLink
    widgets/          PDF viewer, explorer list items, buttons
    starwind/         generated by the Starwind CLI
  lib/
    content/          loader, rules, schema
    pyqs.ts           paper name parsing, titles and sort order
  utils/              URL, string and date helpers
  configs/            site title, links, repository and branches
  styles/             Tailwind setup and site tokens
tests/                unit tests, run with bun test
docs/                 this documentation
pyqs/                 the papers (main branch clone, not committed here)
```

## Tests

```sh
bun run test
```

Tests live in `tests/` and use Bun's test runner (`bun:test`). They cover the loader, the loader rules, paper name parsing and sorting, URL and string helpers, and the build info.

Bun can't resolve Astro's virtual modules such as `astro:content` or `astro:config/client`. Keep testable logic in modules without those imports. For example, `src/utils/url.ts` is pure and `src/utils/site-url.ts` wraps it with the Astro config. The loader tests run the real loader against a temporary folder with a fake loader context.

## Type checks, lint and formatting

```sh
bun run check    # astro check, then tsc for the tests
bun run lint     # Biome
bun run format   # Biome, applying fixes
```

`astro check` does not support TypeScript 7 yet, so the project pins TypeScript 6. The tests have their own `tests/tsconfig.json` that adds Bun's types.

Biome formats with tabs and sorts imports. It skips the files the Starwind CLI generates.

Run `bun run ci` before pushing. CI runs the same script and stops the deploy if it fails.

## Conventions

- Keep the site file-type agnostic. New formats get a file kind, as described in [Architecture](architecture.md#adding-a-file-kind), instead of PDF-specific checks.
- Put derived data in the loader, so pages read it from the content store instead of recomputing it.
- Use `NavLink` for links, and the helpers in `src/utils/site-url.ts` for site paths.
- Use the color tokens and utilities in `src/styles/global.css` instead of palette classes such as `text-red-500`.
- Write comments only where the code can't explain itself, in one or two plain sentences.
- Add or update tests in `tests/` with each change.

## Building locally

```sh
bun run build
bun run preview
```

The build writes to `dist/` and keeps its cache in `cache/`. Incremental builds reuse unchanged pages from that cache. Run `bun run astro build --force` to render every page again. See [Deployment](deployment.md#incremental-builds) for details.
